# Contributing to PlayLiquid GameOS

PlayLiquid uses Git-native contribution semantics.

## Contributions

A contribution can be:
- issue;
- replay-backed bug report;
- code;
- package;
- asset;
- avatar;
- skill;
- world region;
- simulation/evaluation;
- review;
- documentation.

Where a contribution changes executable behavior, it follows the normal Work Order/PR lifecycle.

## Worker execution

Workers implement one Work Order on one branch with one frozen write surface. Workers never merge.

## Human/community contributions

User participation is optional for ordinary autonomous paths. When the Lab requests human capability, the request is explicit, scoped and auditable. External expert escalation uses Arena.

## Evidence

Claims must be reproducible from repository source, tests and runtime/browser/build evidence. Screenshots and agent summaries do not replace executable evidence.
